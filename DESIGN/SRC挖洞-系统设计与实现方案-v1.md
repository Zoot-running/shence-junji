# SRC 挖洞系统：设计哲学与实现方案 v1

> 2026-09-24。配套《SRC挖洞立项书-v1》。本稿 = 讨论定稿的设计哲学 + 初步实现方案；
> 供开新项目直接落地，用户审定后开工。与立项书分歧处以本稿为准（含讨论中的模型修正）。

## 一、设计哲学：对系统建模

**我们要攻击的对象 = 一个信息系统，其存在意义是管理信息的三性质（C/I/A）**。极简地说：让一部分人访问信息、另一部分人不能——即**访问控制**。

**建模（ABAC 状态机）**：
```
允许? = f(主体属性, 客体属性, 环境状态, 操作)
```
- 系统某一时刻处于一个状态：所有主体状态 × 所有客体状态 × 环境状态 的联合。
- 我们作为访问者，直接能改变的是**主体状态**（登录/角色/权益/租户归属…）。
- 漏洞 = f 的行为偏离预期。两种形态：
  - **同态违规**：主体状态 S 内，放行了不该放行的（客体×操作）——资产结构发现+试探主攻；
  - **异态违规**：操作把主体推进了不该到的状态 S'——状态机走查主攻。
- **客体 ID ≠ 属性**：ID 是引用、代指客体本身；属性 = 描绘客体状态的字段（owner/group/可见性/租户）。
- **挖洞 = 穷尽**：穷尽状态、穷尽每状态下的客体与操作，找出偏离预期者——预期判据见神谕管线（第三节）。

**违规分类（粗糙版，攻击面重分类后续慢慢做）**：
机密性破坏（未授权读）／完整性破坏（未授权写）／可用性破坏（SRC 不碰，除合规 DoS 验证外）。

**已裁剪（当前非目标）**：属主时序配合的"先授权→后失权"竞争型洞（如解绑 group 后 B 仍可访问）——发现成本远高于收益，产品阶段再议。

## 二、核心机制：三张表 + 神谕 + 差分 + 证据门

### 1. 主体状态账本 identities.json（shells.json 的"身份版"）
```
[{ "id":"B", "role":"user", "attrs":{"tenant":"t1","groups":["g1"],"plan":"free"},
   "session":{"kind":"cookie","value":"...","expires":...},
   "scope":"账号 B 的会话工件，用于带态探测" }]
```
- 识别信号：JWT/会话 token 解码（最富）、UI/响应差异、403 翻转行为；
- 记录：角色 + 属性向量 + 会话工件 + 已创建客体清单；
- 剪枝：只穷尽**授权相关属性**的转移（角色/租户/所有权/权益）；外观性属性不穷。

### 2. 客体清单 objects.json（差分燃料库）
```
[{ "ref":"/order/124","kind":"order","owner_hint":"B?","attrs":{},
   "source":"创建回执/响应体/JS参数","at":... }]
```
- 客体引用（id/文件名/资源号）从创建回执、响应体、JS 参数里持续采集。

### 3. 资产操作图（攻击图，负边去重）
- 节点 = (端点, 方法, 参数及其属性相关性, 所需主体状态)；
- 边 = 状态转移与资源引用关系；"已覆盖"负边防重；
- 探测优先级按**属性相关性**排：URL 带客体引用/tenant/role 参数的先测，纯静态端点后置。

### 4. 神谕管线（预期从哪来，分层）
- **L0 公共不变量**（零成本默认假设）：带客体引用的端点应校验所有权；敏感操作应鉴权；多租户 API 应隔离；
- **L1 UI 语义差集**：界面暴露 vs API 可达的差集（前端路由/菜单/文档）；
- **L2 差分切片**（最硬，两形态、零时序）：
  ① 客体引用替换：`/order/123→124`、`?file=a.pdf→b.pdf`——放行 = 横向越权候选；
  ② 主体替换：A 创建客体（一次性 setup），B 访问——放行 = 越权/隔离破坏；
  （明确不做：属主配合的转移→复测，即竞争型时序差分）
- **L3 业务规则积累**：按行业/平台沉淀剧本库。
- **判定证据链**（工程中逐步摸索，不钉死）：响应体差异最强；可枚举性为设计缺陷级；双账号交叉兜底。

### 5. 证据门与可信发现管线（四合一）
- 证据门：无真实工具输出的 finding 不标 verified，模型断言降级（T3MP3ST 标准）；
- 逐字证据回执（PentestGPT 思想）；
- proof-by-exploitation：无 PoC 即丢弃（shannon 标准）；
- 双流对账去重 + 二次验证（复测）。
- finding = 假设 + 翻转证据 + 影响面，三者缺一不上报。

### 6. 双层节奏调度（每目标低慢小 × 全网并行）
- 全局：多目标扇出（千企业/万资产，全局万级 req/s）——沿用神策调度内核（槽位/优先级/排满义务迁移为"多目标并行排满"）；
- 单目标：严格低慢小——时间盒迁移为"每目标请求预算"；请求预算器记账 + 封禁退避。

## 三、全流程管线（阶段图）

```
资产发现 → 目标评分 → [挖洞循环] → 验证 → 报告生成 → 平台上传
```
- **资产发现**：被动优先（JS bundle→端点+参数、API 文档、证书透明/公开快照、指纹）；主动有界（小词表目录、认证态参数探测走代理截流）；
- **目标评分**（商业核心，开源项目均无）：烂代码信号 × 赔付意愿信号（强监管行业/历史赔付案例）→ "今天打谁"；双面评分：能不能打 × 给不给钱；
- **挖洞循环**：状态账本/客体清单/资产图 → 同态穷尽（资产+操作+属性变异）→ 异态走查（跳步/重排/重放/换主体，跨主体时序竞态除外）→ 神谕判预期 → 证据门；
- **报告-上传适配层**：各 SRC 平台字段适配，最后一公里。

## 四、架构与组件

- **架构原则**：LLM 为核心（计划层单主脑=御主）；"角色"仅当工具集确实不同时存在（侦察/利用/验证/报告四套工具集），不做人设剧场；**状态出脑**（图+文件+开工必读）。
- **工具清单（10-15 个）**：浏览器级 HTTP（渲染/交互/人工登录态）／代理截流（认证流量参数挖掘）／扫描器子进程（nuclei/ffuf/sqlmap，带词表/时间盒/每目标限速罩）／JS 接口提取（黑盒可达的半白盒：bundle/泄露文件/移动端反编译）／指纹与组件版本／资产发现（被动源为主）／状态图+负结果文件／验证执行器／报告生成器／请求预算器／WAF 绕过知识注入／业务逻辑差分工具（双账号/多角色）。
- **可组装开源件（只抄不搬）**：CyberStrikeAI（黑板+交接包+认证重放）、T3MP3ST（证据门/围栏/dry_run）、shannon（proof-by-exploitation+对账）、PentestGPT（逐字回执状态机）、cai（杀伤链分组+复测去误报）、Nettacker（YAML 模块+历史漂移作已知 CVE 子模块）、Strix（Caido 代理+认证态+报告链）。HexStrike 无价值。
- **合规留证**：每一步攻击动作与授权上下文同落盘（法律盾+报告素材）。

## 五、实现路线（最小闭环先行）

- **P0 最小闭环**：客体清单采集器 + 客体引用替换差分 + 证据门 → 产出第一类 finding（横向越权/信息泄露）。最便宜、最快见洞；
- **P1 状态账本**：identities 采集（JWT 解码+UI 差异）+ 主体替换差分（双账号）；
- **P2 资产操作图**：被动资产发现 + 图落盘 + 负边去重 + 属性相关性排序；
- **P3 异态走查**：UI 反推预期状态机 + 跳步/重排/重放/换主体；
- **P4 双层节奏调度**：请求预算器 + 多目标扇出 + 封禁退避；
- **P5 全流程收口**：报告生成/平台适配/目标评分。
- 每阶段验收：对 1-2 个真实 SRC 目标跑通并产出 finding（立项书验收口径）。

## 六、非目标与边界

不追竞争型时序洞；不做白盒 SAST 主体（保留 JS/泄露文件半白盒）；不打可用性；不接未授权委托；不碰内网渗透/APT 交付；不追求 CTF 速度。
