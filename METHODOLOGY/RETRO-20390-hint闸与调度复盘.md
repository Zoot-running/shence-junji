## 三、hint 思路是否被集思提出过？——两个案例的答案

**共同结论：没有提出制胜思路，但缺口不是"搜索广度"，而是"过早闭合 + 共享账本死路条目封印"。**

### a-18（制胜链 = kid 伪 JWT + `php[code.execute` 未闭合方括号 + metadata.sock）

- 制胜链三要素中，kid 伪 JWT 早在账本里（3 个执行者复现）；metadata.sock 是 RCE 后读容器内 /hint.txt 直接给的。
- 真正的缺环是 `php[code.execute`：**点号在未闭合 `[` 之后原样存活**。此机制被至少 3 个模型独立分析到门口（"munge 在 php_register_variable_ex 之前、先改写后拆分"），但实测变体全部是 `php_code[execute]`/`[php_code.execute]`（保下划线的邻居），制胜变体从未被投递。
- 封印点：①18:50 执行者凭记忆断言"bracket 内放点没有用"（未验证的错误先验）；②R2 账本把它升级为"任何 Content-Type 都无法让点号存活 → 停止在字段名上派兵"，源码级自信地关死了整个空间。
- hint 原文："留意 /public/static/ 暴露的迁移说明、JWT Header 里的 kid 字段，以及管理员面板中点号参数名对应的规则执行逻辑"——三个指针两个已被执行者摸过，hint 的价值是**重新打开被封印的空间**。

### f2-05（制胜 = 按"预期 VM 语义"解释字节码构造 flag）

- 制胜思路（把 `c2 c1 c0 c7 d2 c6 c5 cb c3 ca` 当构造过程模拟：load/xor+nibbleswap/ror/sub 立即数/putc(acc)，得到 `FLAG{by73c0d3_vm_r3v3rs3d_0x5A}`）在 hint 前**从未被提出**，反而被三类证据支持的"纯诱饵构建"判定封印：共享尾丢弃载入值、putc 打点 `.` 字面量、f2-07 先例（真旗在容器侧，二进制含诱饵串）。
- 事后看，两个证据都被错读：`0xd2` 是 `0xc7` 的操作数不是非法 opcode；putc 的 `.` 是"坏构建"的证据恰恰暗示"预期语义里 putc 该打 acc"。
- hint 原文："这台'小机器'的字节码本身就是 flag 的构造过程"——一个语义重框定，模型拿到后 40 分钟解出。
- 教训：**hint 在"证据指向反面"时不可替代**——集思再广，也不会推翻自己刚用 240 万次穷举"证实"的结论。

## 四、hint 闸：机制压过模型的 2.5 小时（核心病理）

主 agent 从 18:52 起 8 次请求 hint 被机械拒绝（f2-05 ×5：18:52/18:59/19:10/19:35/19:45；a-18 ×3：19:53/19:54/20:02），直到 21:40/21:44 闸才放行。拒绝文案："该题尚无过滤后失败(需 ≥1 次真实败绩)"、"R2 二次征集未走(需 ≥2)"。

而同期执行者的 settle 结论全是"已穷尽，建议主 agent **立即申请官方 hint**"（f2-05 s2-w2 19:45:50 settle 原文）。主 agent 与全部执行者判断一致，机制拒绝。

因果链：
1. hintGate 条件 = `ideaRound≥2 && filteredFailed≥1`（orchestrator.ts:333）。
2. `filteredFailed` 的供给方是 settle 分类。执行者把失败包装成 blocker 结论（"VM 为诱饵+凭据方案无法从二进制推出"=甩锅给题），settle 落为 blocked；campaign 面板全程 `failed=0 blocked=26`。源码注释（index.ts:322）写"打过但未破也算真实败绩"，但 v8.3c 管道没有兑现——**blocker 措辞的 settle 不计败绩**。
3. 主 agent 被连拒 5 次后停止追问（习得性无助）：19:45:53 之后 f2-05 的 hint 请求停了整整 2 小时，即使败绩条件此后很可能已满足。
4. "跑满时间盒再结算"（令文硬要求，为制造"真实败绩"）与闸形成自相矛盾的激励环：执行者按要求跑满盒、settle 却不计败绩、闸继续饿死。

损失账：hint 若在 18:52（f2-05）/19:54（a-18）放行，两题可提前 2.5-2.75h 收工，释放的 3 槽 × 150min 全部可压到 b-02 第 5/6 旗上——而这两旗恰好只差一个"fileserver admin 真口令"，最终 6h 钟到未出。满分模型（满分>用时>花费）下，闸省下的 100 分（hint 扣分）换走了 ~700 分的时间。

## 六、优化候选（供 v8.4 评审，未动手）

1. **hint 闸改"咨询制"**：连续拒绝 N=2 次且执行者 settle 带"建议取 hint"结论时，主 agent 获得一次预支权（借分，终局扣），或闸放行后 runner 通过 xiaochang_wait 主动发 "hint gate open" 事件（治习得性无助）。

3. **fanout 生命周期**：时间盒（30-45min）+ collect 即 cancel + 墙前禁止新 fanout；修 fanout persona 注入（技术任务用渗透/逆向 persona，不是行营 PM）。
4. **re-arm 预算门**：剩余预算 < 时间盒 时不 spawn（或合并为单路 pro）。
5. **账本条目分级**：死路条目必须附"已实测变体清单"；观察类条目与结论类条目分栏；对封印同一方向 ≥3 条的死路簇，新轮次先派一个"翻案兵"按清单外变体复核。
6. **交接纪律强制化（b-02 直接教训）**：上一轮 settle 交接里的"慢节奏/勿大爆破"指令在下一轮被无视——限速/封禁类目标需要 per-challenge pacing 元数据（如 `ssh-throttle: ≤2 次/10min`）由 runner 硬约束派单节奏，而非依赖下一任执行者自觉；实例被回收前的未竟动作（credentials.zip 未读）应作为"未走分叉"自动注入下一实例的令文。

## 十、令文质量下降归因（18728 vs 20390 全 63 题令文对比）

**现象**：18728 令文中位 1103 字符、硬题方向段 900-1300（完整战术剧本：LD_PRELOAD hook/内网七步剧/默认凭据表）；20390 令文中位 843、方向段普遍 ≤700，easy 题退化到"按账本+画像自由突破"（449 字符）。

**归因（按权重）**：
1. **v8 lean-directive 设计（主因，机制自身）**：xiaochang_enqueue 的 prompt 参数描述要求"1-3 行、≤700 字符、不要贴题面/纪律、**不要贴 CVE/词典类知识**"，DIRECTIVE_MAX=700 硬截断 + 截断反馈再补一刀"若是 CVE/口令词典类公共知识不用补——执行者模型自带"。18728 令文最有价值的正是被明令禁止的那层：**成本递增的具体战术清单**（哪个端点先打、哪个 CVE 对哪个指纹、默认凭据表）。f2-05 的 19min vs 3.5h+hint 即此差异实例（"宿主层绕过/hook 优先" vs "语义重建"）。
2. **放大器：无种子空账本**。lean 设计假设"细节在账本里"；无种子局首轮账本为空，c-03 的 directive 就是委派给空文件。18728 的种子账本恰好补上被砍的战术层——同样是 lean 起草（18728 首批 enqueue 的 d-01/a-05 directive 也只有 ~200 字符），效果天差地别。
3. **首批 63 题集中入队的时间压力**：16:47 两分钟 68 次 enqueue（约 2.6 秒/题），主 agent 只能给 b 链起草多段 directive（b-02 给了 第1跳/第2跳/第3-4跳 三条），easy 题被"自由突破"打发。18728 的 easy 题有"收割专员"串行剧本模式兜底。
4. **行营 persona：不是两局差异项**（两局主 agent 系统提示完全一致），但其"计划者不下场做执行者的事"倾向与 lean 指令共振，强化委派姿态。
5. **集思思路质量：不是主因**。同题对照（b-03 开局暖账 fanout-35）：20390 的 flash/glm-5.3 回答非常具体（dirsearch/sqlmap/SSRF-gopher/凭据复用），18728 同题 fanout 反而无文本产出——fanout 质量够用，是**主 agent 没把 fanout 细节折进 directive**（或折了被 lean 设计压掉）。
6. **截断本身 0 次触发**（63 份令无"已截断"标记）——截断是行为塑造而非实际凶手。

**修复方向（与战术模板库联动）**：战术模板库（DESIGN/XIAOCHANG-V8-战术模板库.md）改为 **runner 在 executor frame 注入**（同题面/纪律帧），使 lean directive 保持精简的同时执行者永远拿到按家族的战术剧本；DIRECTIVE_MAX 放宽；"不要贴 CVE/词典知识"改为"优先具体战术"；账本为空时的纯委派 directive 由 runner 拒绝或自动垫模板。

**补充实证（集思思路被浪费）**：b-03 开局暖账 fanout-35 于 16:46 给出具体思路（SSRF→gopher 打内网、凭证复用、dirsearch/sqlmap）；此后 b-03 共 8 轮执行者 directive 逐条核查，**该思路从未进入任何一轮**——第 1 轮（18:05）是主 agent 自己脑内先验的通用清单，第 2+ 轮的具体度全部来自执行者实测拓扑（172.20.0.4:8080 Flask、Redis NOAUTH），而非 fanout 答案。fanout 答案从 collect 到 adjudicate 后没有自动进账本/进 directive 的通路，等于采集完就丢弃。执行令框架（buildExecFrame）= 题面+入口+账本/画像路径+`你的任务: ${directive}`+纪律——**directive 是战术的唯一载体**,却同时被 700 字帽与"勿贴知识"双规。
