## 一、打包排障链(镜像管线教训, 全部踩坑实录)

1. **20722 wait_expired**: 重装四件套插件时漏了 `@shence/xingying`(profile bundles 引用但 dependencies 里没有)→ 驱动启动即崩 "cannot resolve profile bundle @shence/xingying"。**教训: hosted 镜像 profile 有五个 @shence 插件, 重装必须五件全装**。
2. **20727 wait_expired**: `plugin add file:` 重装后 pnpm 把 `@deepseek-ai/*` peer 依赖解析到公共 npm 的 **0.0.1-rc.1**(缺 `brandString` 导出), 与镜像内 DSH 结算(0.1.3-alpha.1, 私有 registry)不匹配 → "dsh-brand does not provide an export named brandString"。**修法: 删掉 profile .pnpm 里所有 @deepseek-ai 影子副本, 让解析落到 profiles/node_modules 的 0.1.3-alpha.1 全集**(本地复现验证 jisi/dsh-compat/xingying import OK + 全 profile boot "ok")。
3. **20733 幽灵授予泄漏**(v8.4.2 修复): 跑到 3.5h 发现 containerQueue granted=3/3 但仅 1 槽在转(grantedCodes=1), 2 槽死锁 40+ 分钟、37 题排队空等。根因: `grantAndSpawn` 授予落地时题已不在 queued(裁决/降级竞态)直接 return **不归还队列槽位**; armQueue 授予回调同样缺状态漂移防御。修: 两处归还槽位 + 审计 `v8-grant-miss`/`v8-arm-grant-race`。20777 全程 grantedCodes 与 openContainers 对齐(3=3=3), 泄漏未复现。
