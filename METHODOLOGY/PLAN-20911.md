# 计划：tsecbench v1 本地实验局 run 20911（v8.5.1 机制实验 + 打题）

## 目标
- 硬指标：得分最大化（23000 分 / 63 题），同时逐条验证 v8.5.1 机制观察清单。
- 资源：74 分钟墙钟（14:00 停表）、平台容器槽 3 个（containerSlots=3，硬瓶颈）、63 题全为容器题。
- 优先级字典序：满分 > 用时 > 花费。

## 依赖图（关键路径）
1. 开局：create_goal → xiaochang_setup(runId=20911, token, budget 74) → xiaochang_list/status。
2. 全题按 total_score 降序投思路（63 题至少各 1 条 directive）→ 队列 armed。
3. 机制自动授予容器（3 槽）→ 执行者开工 → 旗仓 pending → 主 agent 提交 → 采纳/裁决。
4. 每轮：status（在途清单+资源读数+未破题行）→ 排满度检查 → 补兵/收兵 → wait。

## 关键路径与并行扇出
- 关键路径：**槽位周转率**（3 槽 × 时间盒 30min）→ 决定可跑题数上限（约 9-12 题）。
- 扇出 1：dispatchNow 在 granted 题上并行加兵（每槽 2-3 路），把空闲资源（loadavg<1、mem 3/12GB）填满。
- 扇出 2：jisi_fanout_bulk 多模型征集思路（batched，notify 模式），报告到达 → idea_adopt → enqueue(ideaIds) 派兵。
- 汇合点：旗仓（xiaochang_flag_report）→ 主 agent 单点 submit。

## 资源上限证明
- 容器槽 = 3（平台硬限），本地/附件题 0 个，故并行度上限 = 3 容器 × N 兵；N 由容器资源读数决定（当前 loadavg 0.16-0.57，mem 3/12GB → N 可到 2-3）。
- 主 agent 工具调用为唯一串行段；等待全部走 xiaochang_wait（零 token）。

## 执行者分工
- 执行者（deepseek-v4-flash 默认 / deepseek-v4-pro 用于关键路径加兵）：按 directive 打题，出旗即 flag_report。
- 调度（主 agent）：排序、加兵、收兵、rotate、采纳思路、提交旗、裁决。
- fanout 模型（kimi-k3 / deepseek-v4-pro / deepseek-v4-flash）：只出思路，不碰目标。

## 验收与停止条件
- 逐题：flags 全齐 → report(complete) 立即释放槽位；主动换实例 → report(rotate)；判死需 ≥3 不同思路兵力。
- 全局停止：**14:00 到点或满分** → xiaochang_finish(force=true) 停表（本地局无 guard，必须由主 agent 自己收尾）。
- 机制验收：11 条观察清单逐条回填战报，成败同权重。
