# 复盘分类机制（RETRO-CLASSIFICATION）

> 方法论 POC W2 交付物之二。适用：每次战役/任务战后的教训落账与分类（PDCA 的 C→A 段）。
> 原则：**成败同权重**——败仗复盘更值钱（run 8 的教训造出了 run 9 的满分）。

## 一、复盘模板（四栏）

1. **预期 vs 实际**：目标/用时/花费/行为指标（亲解数、并行扇出、被拒判死数等）逐项对照。
2. **决策-结果对照**：关键决策列表——当时的选项 / 选了哪个 / 结果 / 反事实（选另一个会怎样）。这是给"下一次的 agent"的训练数据。
3. **根因**：对每项偏差做归因（5 层 why 或直接归因），区分：提示词问题 / 机制缺口 / 平台侧 / 环境侧。
4. **教训分类**（见下节四桶）——每条教训必进一桶，写清去向。

## 二、分类桶与去向

| 桶 | 定义 | 去向 |
|---|---|---|
| **A. 通用方法论** | 可溯源公开技艺或自研、不涉具体题的判断/调度/技术启发 | **升格进 SKILL 合规层**（先验证再固化：run 中实测有效才固化） |
| **B. 机制先验/题源启发** | 平台行为观察（ARCH-OBS）/具体题解法捷径 | **`local/hosted-priors.md` 私知**（gitignore，不进托管 run prompt；平台书面确认后可升格） |
| **C. 一次性事实** | 某 run 某题的特定状态/结果 | **归档进对应 L4 战报** |
| **D. 平台缺陷** | 留证充分的平台运行故障 | **平台反馈文档**（渠道可用时；否则留 C 桶待机） |

## 三、升格流程（C→A 的闭环）

战后复盘 → 分类 → A 类按"先验证再机制化"提交 SKILL 修改 → 下一 run 验证 → 通过则固化，不通过退回桶。

## 四、回填责任与时限

- 主 agent：战役结束后随战报完成四栏初稿（本会话内）；
- 人工回审：用户在下一次对话中审"决策-结果对照"，纠正分类桶；
- 时限：战后 24h 内（跨 run 间隔窗口）。
