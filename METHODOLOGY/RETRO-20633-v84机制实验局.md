## 二、本局暴露的两个 bug（v8.4.1 已修并推送）

1. **排题失效（B1）**：`priorityOf` 的"从未开工公平带"里 `(2000-base)*10` 让 **easy 反超 hard**，且显式 `priorityOverride` 冲不出 1_000_000 段——"难的先来"完全失效：开局 3 槽被 easy 占满、FIFO 固化，b-02（1800 分）排到 55-63 位、8 条令全部沉没，直到末段 40min 才拿到容器。
   修：override **直通排序**（跳出公平带）；带内改分值密度（hard 优先）；enqueue 显式 priority 变更时 evict 已武装容器题**全量重排**。
2. **ideaIds 短标签静默 no-op（B2）**：adopt 落盘 id = `<code>-<id>`，主 agent 传短标签 `<id>` 时 `markIdeasConsumed` 静默忽略（"无副作用"式失败——最危险的一种）。修：后缀匹配 + 未命中响亮反馈候选清单。

## 三、其余实战教训

- **全题预投令是排题不可控时的唯一正确解**：59 旗的直接原因（任何被授权的题立即有令可打）。
- **高价值长尾在 FIFO 下=最后才打**：攻坚模型配额应投给确认能拿到槽位的题。
- **driver timeout 与 finish 竞态**：20:29:41 timeout 掐断 driver、finish 未落地，平台钟空转——launch 侧兜底由监控者外部调 finish 停表（本局已做，final_flags=59）。下次 driver timeout 应留 ≥90s 收尾余量或在 wrapper 里兜底 finish。
- easy/medium 是分数基本盘：c- 9/9、d- 6/6、e- 14/14 全清；hard 500 档 12/15 出旗；f2-05 本局为 decoy 构建（执行者判死未编造旗）。
- 账本① 的"(未消费)"标记不随派兵更新（cosmetic；status/enqueue 回显才是真相，SKILL 已注）。
