- v7.6 把"排队"机制化,但队列单元是**执行者**;容器从此有三个写者:主 agent 直接调、

## 三、"一题多 agent 多思路"设计史:为什么做成单兵先行,多 agent 有没有冲突

### 1. 不是冲突杀的,是 run 8 的成本-收益实证杀的
- 原始设计(09-10 之前):"难题每道并行多条思路(5+ 执行者同打一题),easy/medium 至少 2 路并行"。
- `2c5aa86`(09-10 14:02)改成"easy/medium **单兵先行**,卡住/超时再补第 2 路",理由原文:
  "run 8 实证:6 道离线 medium 单执行者全部正确解出,**多路对确定性数学题只是重复算同一个值——
  方向探索才需要多路**"。弃因 = 重复计算烧钱,不是 agent 互踩。

### 2. 多 agent 没有死,被拆成两层
- 思路层:**jisi_fanout 全模型并行征集**(便宜、无容器、无冲突)——多思路价值保留在这里;
- 执行层:单兵先行 + hard 题保留 5+ 多路 + R2 升级加模型——多执行者降级为升级手段。
- `7a25106`(09-13)收割专员制(run 11 转折点):"当'已备好脚本/思路、只差容器槽'的题堆积时,
  **不要让 N 个执行者各自抢槽**"——这是 3 槽 × 63 题的**稀缺资源第一定律**(机会成本),
  不是 agent 冲突。一槽一执行者 = 每分钟旗分最大化。

### 3. 冲突实况:存在,但都是次要形态
- 板文件写竞争:19429 f1-02 glm 写 FINDINGS.md 撞 "file has not been read"(兄弟执行者刚写过);
- 工件交叉污染:19429 f1-02 flash 捡了 glm 留下的 cli.py(默认端口 127.0.0.1:9000),
  白打一堆 localhost 探测;
- 重复饥饿报告刷屏:18:03 一波 5 个执行者各写一份"收工,由主 agent 调度"。
- 对照:18728 的"开工先读账本"纪律让多路补位**零冲突**——c-03 重打轮执行者
  (sid 801925)先读战报拿到 rce.py,在新容器实例 20 秒重打成功,**还发现容器轮换会换 flag**
  (.34 的旧 flag 随容器失效,.33 出新 flag)——多路在此是纯增益。

### 4. 结论
- 单兵先行/一槽一执行者本身没错:18728 的单兵传送带(收割专员)赢了;
- 错在 v7 机制把"多路=升级层"重新放开后,**没保住两个让多路安全的不变量**:
  ①开工先读账本(思路复用而非重复计算);②槽与兵原子绑定(有兵必有题可打)。
- 19429 的退化形态 = **多执行者 × 零容器 × 零账本增益**:a-18 六兵连打、f1-02 双兵空转、
  五执行者同时挨饿——多路的名义,单路的实际,双倍的浪费。

## 四、根因与方向(v8 提案)

**根因一句话**:队列装的是执行者而不是题;容器生命周期三权分立;"某题无在途执行者"没有任何机制追踪。

**方向(待评审)**:
1. 队列单元 = 题(态机:未开工→排队→抢槽→原子授予→结算→出旗出队/未破回队带退避);
2. 槽授予原子化:启容器 + 绑执行者 + 注入账本 = 一个动作,杜绝"启动了没人打";
3. 主 agent 只剩队列管理(优先级/hint/裁决)+ 验收 + 收旗,砍掉 start/close/enqueue 组合拳;
4. "无攻击面/环境缺失"类 blocker 结论需第二执行者独立确认才入账;hint 闸把 blocked 也计为失败;
5. 未破题仪表全量 + 按"0 在途优先/从未开工优先"排序,不截断;
6. 收割传送带:结算释放的槽立即给队首,执行者会话可热复用(18728 已验证)。
