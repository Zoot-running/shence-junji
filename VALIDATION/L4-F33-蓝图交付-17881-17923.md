## 3. 本轮抓出的两个真 bug(托管轮实锤,本地修复)

1. **模块级 helper 引用 apply 闭包变量**(run 17881):knowledgeOfCode/recordKnowledgeOnCode 插在模块作用域却引用 apply 内的 campaign/campaignId/holder → ReferenceError `campaign is not defined`;执行者 fork 全错、report 带结构化字段时落账抛错会中断关容器/剪枝主线、主 agent 被迫回退 hufu_enqueue。修复:helpers 移入 apply 闭包 + 全部知识操作 try 包裹(记账尽力而为,调度是主线)。
2. **in-memory 跨会话通道不可达**(run 17891):执行者会话与主会话不在同一插件实例——`parentAgent.followup` 与 in-memory campaign 均到不了主 agent(实测 graph 零吸收、wait 零唤醒、fork 结果虚假宣称"已唤醒")。修复:**盘上分叉信箱**(`DSH_HOME/storages/xiaochang-fork-inbox/<code>.jsonl`):执行者 fork O_APPEND 写盘 → 主 agent 的 xiaochang_wait 第 5 唤醒源(目录 mtime/size 2s 轮询,与账本轮询同机制)→ 读图即吸收(去重并入账本+归档)。该通道跨会话/跨进程/跨 guard 重拉都可靠。
