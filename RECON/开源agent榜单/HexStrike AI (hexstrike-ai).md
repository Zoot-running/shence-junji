# HexStrike AI (hexstrike-ai) 分析报告

- **能力范围**：部分流程
- **SRC 适用度**：低——本质是现成扫描器的 subprocess 封装，'AI'为硬编码模板/打分表，无 LLM 规划与上下文记忆；漏洞判定靠关键字计数，重侦察轻利用验证，无报告/修复闭环。

## 核心思路
让外部 LLM(Claude/GPT/Copilot 等)经 MCP 协议调用 150+ 已封装安全工具，并用规则式'决策引擎/工作流'自动选工具、调参、并行链式执行——代码内并无真实 LLM 推理。

## 架构
两段式：FastMCP 客户端(hexstrike_mcp.py)暴露150+工具，HTTP 转发到 Flask 服务端由 subprocess 执行外部工具；内置确定性决策引擎(分析目标→按有效性打分选工具→参数优化→线程池并行)，配进程池、LRU 缓存、故障恢复、Selenium 浏览器代理与可视化引擎。

## 技术面
黑盒扫描器聚合(封装 150+ 工具)；规则决策引擎(工具-目标有效性打分+参数优化+攻击链模板)；MCP 工具暴露；浏览器代理(Selenium+mitmproxy+DOM 分析)；CVE 情报(NVD/GitHub 检索+模板化 exploit)。

## 短板
无真实 LLM 自主规划；需自装 150+ 工具、直接执行任意命令无鉴权沙箱；漏洞判定靠关键字计数误漏报高；无状态记忆与验证/报告闭环。

## 值得神策借鉴
MCP 瘦客户端+HTTP 工具服务端分层解耦；工具-目标有效性打分+参数优化模板做冷启动决策；线程/进程池+LRU 缓存+失败降级的工程化执行层。
