## 二、满分局三个共同点（可复制的硬约束）

1. **0 hint**。21881/22428/22436 全部 0 hint。对照实验：Salvo 74/74 全旗、仅 1 次 hint 扣 120 分 → 99.43 → 第 4；我们 74 旗 4 次 hint 扣 ~322 → 98.6 → 第 6。**满分 = 0 hint，没有例外**。我们的 4 次 hint 当局是 ROI 正向（290 分换 b 链 2460 深旗，RETRO-21154 已记），但现在 b 链解法已进 junji，下次可以 0 hint 重跑。
2. **deepseek-flash 单模型 + 平台 3 实例槽封顶**。四强全是单模型（我们 9 模型是异类）；峰值并发全被平台锁在 3，吞吐来自"槽内微任务高频切换"（CyberSwarm 392 会话跑在 72 个实例生命周期里），不是加实例。
3. **b 链全取 + 用时长尾换分**。四强 b 链 14/14。哨兵v2 用 24 个 runtime worker + 2 小时磨 b-02 后两旗；Salvo 深旗长尾 135 分钟。深链要留长期 lane，不能全是短任务。

## 五、架构收敛观察：任务图/事实黑板成为主流（前 12 名中 7 队）

四种接力形态：
1. **共享 checkpoint 专用工具**（哨兵v2，21611 同款）：`tsecbench__get_shared_checkpoint` + blackboard + ResourceManager + 运行时 `delegate_task`/`runtime_worker` 第二 group。
2. **YAML 任务图注入**（CyberSwarm）：无专用共享工具；会话返回结构化 JSON 事实 → 编排器合并成 `facts/intents` 图 → 下一会话注入 YAML + Current Intent + conclude phase 强制收敛。事件溯源式，可审计可分叉；代价 249M cache_read。
3. **checkpoint 序列化**（Salvo）：新会话首消息注入完整 `<conversation-checkpoint>`：objective/requirements/decisions/work-state/next-move/relevant-files/important-context；共享文件/tmux/隧道/mycel memory 存真实状态，新会话开局探活不重扫。
4. **知识召回层**（BinEvi）：任务图之外加 `search_knowledge`（KB 只给假设和 payload，不自动升级为事实）+ 跨题凭据表（"候选必须当前实例复验"）+ 阶段 checkpoint。

另有少会话重执行派（Pentest4DSH 132 会话、Heimdall 237 会话长上下文）居后，说明**会话数不是排名变量，事实图的状态一致性和提交纪律才是**。

## 六、可借鉴清单（落地候选，改前须讨论）

### 对神策 runner（tsecbench 打法）
1. **提交幂等层（最高优先）**：CyberSwarm 29 次错答中 25 次是 b-02/b-03 并行分支重复提交/同秒竞态。我们已有"已交旗位注入执行令"，但缺 `(challenge, candidate_hash)` 去重 + 已解决题冻结 + 同秒候选 singleflight。
2. **执行/收敛分相**：编排器发 conclude 信号，让将超时/已穷尽的执行者只返回结构化事实，不继续打。我们靠 timebox 硬切，缺"收口 schema"。
3. **0 hint 纪律进入下次开战令**：知识库现在覆盖上次 hint 的题目，下次 tsecbench v1 应设 hint 预算=0 目标（b 链解法在 junji）。满分局证明可行。
4. **三槽高吞吐调度**：按 `expected_score/estimated_time/confidence/unlock_value` 排 intent，快速单旗与深链解锁并行（我们有 dispatchNow/fanout，但槽内切换粒度可更细）。
5. **错答预算统计**：四强错答最少的是哨兵v2（2 次）；把"同题错答≥2 即换方向+原因归档"写进纪律。

### 对 SRC 挖洞项目（shence-src-hunter DESIGN v2 的补强素材）
1. **Salvo checkpoint 字段设计直接对口微会话判穷尽**：`objective / verified_facts / live_footholds / credentials_refs / excluded_paths[{hypothesis,evidence}] / artifacts / blockers / next_queue / lease_deadline / stop_condition`。两层：事实层不可变带来源时间戳；执行层可失效（cookie/shell/隧道/作业）新会话先探活。
2. **判穷尽 = 覆盖矩阵 + 路径级证据**：每个漏洞面维护已测 source/sink、编码层、协议变体、权限角色；`exhausted` 必须附已覆盖手法和最后证据，禁止"试了很多"式不可复核结论。与 SRC 设计 v2 的"主模型判穷尽"完全同构。
3. **封禁规避当状态机**（哨兵v2 实测）：`reachable → throttled → cooldown → recovered`；SSH 爆破拒绝后降单通道、拉长间隔、切换证据源。比"换 IP"更根本——SRC P0 可直接采纳。
4. **图式 pivot 长链 lane**（CyberSwarm）：入口事实→SSRF/文件读→内网资产→凭据→新服务→提权，每步带证据和可回滚 intent；执行者只取依赖闭包。对应 SRC P1/P2 状态图。
5. **知识召回与现场证据分层**（BinEvi）：KB/历史 Note 只能给假设和 payload，只有当前目标实测才能进 Fact；跨目标凭据复用前强制复验。适合审计与提交证据。
