## 可取之处（对神策与 SRC）

1. **封禁规避：把限速/封禁当状态，不当“再试一次”异常。** b-02 SSH 爆破导致 connection refused/timeout 后，worker 会停任务、降为单通道、延长间隔并切换证据源。神策/SRC 可把 `reachable → throttled → cooldown → recovered` 写进资产状态机，统一控制并发、重试预算和源 IP，避免多个执行者互相加剧封禁。
2. **状态图：对象→意图→事实/发现，并保留失败边。** 黑板不是纯文本战报：目标、已排除路线、凭据、内网主机和下一步都有父子关系。可将现有战报账本升级为可查询状态图，让接力者直接拿“证据 + 已排除 + 未决假设”，减少重复扫描。
3. **微会话：按可验证动作切分，不按固定 30 分钟切分。** 425 会话覆盖 63 题，每题 2-20 会话；短会话从 checkpoint/黑板恢复，执行一个探测、一次静态分析或一个凭据矩阵，再落盘。适合 SRC 多资产并行，但需要全局并发阀门和按目标的互斥锁。
4. **判穷尽：失败不是次数，而是搜索空间覆盖率。** f2-07 在 decoy 失败后转成“校验函数→哈希参数→前像空间”；b-02 则记录已试用户×口令矩阵、真实拒绝与限速错误。神策可要求每条路线显式声明候选空间、已覆盖比例、停止条件和替代证据源，避免“试了很多”这种不可复核结论。
5. **0 hint 策略：允许用时间换分，但必须有截止线。** v2 在 f2-05 自解、b-02 用 worker+字典磨出后两旗，拿到 100 分；但总用时反而比 21611 慢 701s。SRC 场景可借鉴“高价值链允许延长、低价值链按边际收益收兵”，而不是全局禁用外部提示或无限深挖。
6. **运行时委派只传已验证上下文。** worker 标题包含入口、内网 IP、端口和服务指纹，减少重复侦察；但应标注来源与置信度，避免把主 Agent 猜测升级成事实。

## 口径与限制

- LLM session 详情端点必须带 `from/to`，且单次最多 50 step；本次按 30 秒窗口拼接关键会话。
- 详情流包含组级累计上下文重放，同一早期 step 会出现在多个会话；因此报告只对抽样调用做跨文件去重，不把它解释为全量工具频次。
- 21611 原报告标题中的 7318s 与 21881 的 8019s均按最后旗/计分用时比较；墙钟另列，避免与 API 的赛程上限 `duration_seconds=21600` 混淆。
- `harness_name`、`harness_version` 在 run API 中为 null，无法从公开字段比较版本号；架构变化依据会话结构和工具事件判断。
